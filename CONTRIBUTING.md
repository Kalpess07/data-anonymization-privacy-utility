CONTRIBUTION GUIDE

Project: Data Anonymization and Privacy-Utility Trade-off in ML Models
Repository: data-anonymization-privacy-utility

1. PROJECT OVERVIEW
This repository contains our research project on data anonymization and its impact on machine learning model performance.

2. BRANCHING GUIDELINES
- main: Contains the stable project version.
- Feature branches: Used for individual tasks and new features.
- Create a separate branch before making significant changes.

Example command:
git switch -c feat/documentation-update

3. COMMIT MESSAGE GUIDELINES
Write short, meaningful commit messages that describe the change.

Examples:
- docs: add contribution guide
- docs: update project README
- feat: add CSV upload interface
- fix: handle missing values

4. PULL REQUEST WORKFLOW
1. Create a feature branch.
2. Make the required changes.
3. Review the changed files.
4. Commit and push your changes.
5. Open a pull request to merge the branch into main.
6. Ask a teammate to review the changes before merging.

5. TEAM COLLABORATION
- Coordinate before editing the same sections or files.
- Inform teammates about significant changes.
- Do not commit passwords, API keys, or confidential datasets.
- Test code before submitting a pull request.

6. CODE AND DOCUMENTATION QUALITY
Keep filenames descriptive, document important steps, and ensure that instructions are reproducible.

7. REVIEW CHECKLIST
[ ] Changes match the assigned task.
[ ] Files have descriptive names.
[ ] Commit messages explain the changes.
[ ] Code or documentation has been reviewed.
[ ] No sensitive information is included.
